HTTP Status Codes ===>

| Code | Meaning | Kab use karenge |
|---|---|---|
| `200` | OK | Successful GET/UPDATE |
| `201` | Created | Successful POST |
| `400` | Bad Request | User ne galat data bheja |
| `401` | Unauthorized | Login/token missing/invalid |
| `403` | Forbidden | Permission nahi hai |
| `404` | Not Found | Resource nahi mila |
| `409` | Conflict | Duplicate email etc. |
| `500` | Server Error | Server-side unexpected error |

JWT ka basic structure
JWT generally 3 parts ka hota hai:
HEADER.PAYLOAD.SIGNATURE

Example:
xxxxx.yyyyy.zzzzz

Header
Batata hai token kis algorithm/type se related hai.
Payload
User-related claims/data.
Example conceptually:
{
    "userId": "123",
    "email": "mayank@gmail.com"
}

Signature
Token ko verify karne ke liye use hota hai.
⚠️ Important
JWT payload ko secret storage mat samajhna.
JWT ka payload generally encoded hota hai, encrypted nahi. Isliye:
❌ password JWT me mat daalna.
Good:
{
    "userId": "123"
}

Bad:
{
    "userId": "123",
    "password": "mayank123"
}
